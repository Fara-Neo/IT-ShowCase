## 4. План следующих этапов

### Этап 1 — MVP: шоурум + заявки (3–4 недели)
Полностью рабочий публичный сайт с каталогом проектов, страницами проектов, формой заявки и email-уведомлениями. Базовая авторизация и роли. Административная панель для управления проектами и заявками. Загрузка изображений через Cloudinary. Адаптивная верстка, поддержка тёмной/светлой темы.

### Этап 2 — SEO, UX-полировка, онбординг продавцов (2–3 недели)
SEO: `generateMetadata()`, OG-теги, `sitemap.xml`, JSON-LD. Верификация email, восстановление пароля. Профиль продавца (публичная страница). Личный кабинет пользователя: история заявок. Категории проектов через админ-панель. Seed-данные для демонстрации.

### Этап 3 — Онлайн-оплата (3–4 недели)
Интеграция платёжного провайдера (Stripe / ЮКасса). PaymentIntent при покупке, webhook-обработчик подтверждения. История транзакций. Комиссия платформы (take rate).

### Этап 4 — Социальные функции и рейтинги (2–3 недели)
Отзывы и оценки (1–5 звёзд). Избранное (wishlists). Внутренние уведомления. Базовый мессенджер покупатель↔продавец.

### Этап 5 — Полноценная биржа (1–2 месяца)
Escrow-механизм. Полнотекстовый поиск. Публичный API. Аналитический дашборд. Программа аффилиатов.

## 5. Known Issues

На данном этапе код не написан, поэтому технических багов нет. Зафиксированы проектные риски:

| # | Риск | Приоритет | Комментарий |
|---|---|---|---|
| 1 | Загрузка файлов >4,5 МБ через Vercel Serverless Functions — ограничение платформы | High | Решение: прямая загрузка на Cloudinary через signed upload, минуя API Route |
| 2 | Отсутствие rate limiting на форме заявки — риск спама | High | Решить на Этапе 1: `upstash/ratelimit` или middleware-счётчик |
| 3 | FOUC (вспышка белого) при смене темы в Safari | Low | Решается правильной конфигурацией `next-themes` с `attribute="class"` |
| 4 | Prisma Client в Edge Runtime (middleware) требует отдельного подхода | Medium | Не использовать Prisma в `middleware.ts` — только JWT-проверку |

## 6. Следующие шаги для разработчика

Если вы начинаете работу над проектом, рекомендуемый порядок:

1. **Прочитайте** всю документацию в `/docs` — особенно `ARCHITECTURE.md` и `TECH_STACK.md`.
2. **Инициализируйте** проект (`create-next-app`) согласно инструкции в `TECH_STACK.md`, раздел 4.
3. **Настройте** локальное окружение: PostgreSQL (или Docker), `.env.local`, Mailtrap для email.
4. **Начните с авторизации** — она является фундаментом для всех остальных фич (роли, middleware, сессии).
5. **Следуйте** структуре папок из `ARCHITECTURE.md` — не отклоняйтесь без причины, это облегчит масштабирование.
6. **Создавайте ветки** по схеме: `feature/auth`, `feature/catalog`, `feature/request-form`, `fix/...`.
7. **Обновляйте этот файл** по мере выполнения задач — переносите пункты из «не начато» в «завершено» с датой.
